# OAuth 2.0 Token Introspection (RFC 7662): Validating Opaque Tokens across Microservices

When designing secure distributed microservice architectures, authorization is often handled using structured JWTs (by-value) or opaque tokens (by-reference). While JWTs are popular due to stateless validation, they expose internal claims to clients, suffer from difficult revocation, and inflate request payloads. Opaque tokens mitigate these issues, but they require microservices to perform real-time verification via RFC 7662 Token Introspection.

---

## The Problem: The Introspection Latency Choke

An opaque token is a cryptographically strong, random string (e.g., a high-entropy UUID or hex key) generated by an Authorization Server (AS). It contains no readable data itself. To validate it, a downstream microservice must send an HTTP POST request to the central AS introspection endpoint.

At high traffic volume, this introduces severe architectural liabilities:
1. **Introspection Endpoint Hammering:** If every microservice queries the AS on every internal HTTP call, the AS becomes a single point of failure and a scaling bottleneck.
2. **Network Latency Overhead:** Adding a blocking HTTP handshake to every service invocation adds 10-100ms of latency per hop, degrading user experience.
3. **Secret Security Management:** The RFC 7662 spec requires the introspecting client (microservice) to authenticate itself to the AS. Hardcoding credentials across dozens of services increases the attack surface.

---

## Technical Architecture: Token Translation Gateway Pattern

To solve the latency and security overhead, use the **Token Translation Pattern** at the API Gateway. The external client presents an opaque token. The Gateway performs a single, cached RFC 7662 introspection against the AS, translates the result into an ephemeral, cryptographically signed *internal-only JWT*, and propagates that JWT downstream.

```
+--------+             +---------------+             +-------------------+             +---------------+
| Client |             | API Gateway   |             | Authorization     |             | Downstream    |
| (SPA)  |             | (Auth Proxy)  |             | Server (RFC 7662) |             | Microservice  |
+--------+             +---------------+             +-------------------+             +---------------+
    |                          |                               |                               |
    | 1. GET /api/data         |                               |                               |
    |    (Opaque Token)        |                               |                               |
    |------------------------->|                               |                               |
    |                          | 2. Check local cache          |                               |
    |                          |    (Opaque -> Introspect Res) |                               |
    |                          |    [Cache Miss]               |                               |
    |                          |                               |                               |
    |                          | 3. POST /introspect           |                               |
    |                          |    (Basic Auth + Token)       |                               |
    |                          |------------------------------>|                               |
    |                          | 4. Returns JSON:              |                               |
    |                          |    { "active": true, ... }    |                               |
    |                          |<------------------------------|                               |
    |                          |                                                               |
    |                          | 5. Populate Cache (TTL 60s)                                   |
    |                          |                                                               |
    |                          | 6. Sign Ephemeral Internal JWT                                |
    |                          |    (Context & scopes)                                         |
    |                          |--+                                                            |
    |                          |  | Dynamic Translation                                        |
    |                          |<-+                                                            |
    |                          |                                                               |
    |                          | 7. Forward GET /api/data with Internal JWT                    |
    |                          |-------------------------------------------------------------->|
    |                          |                                                               | Checks sig
    |                          |                                                               | & claims
    |                          |<--------------------------------------------------------------| (O(1))
    | 8. HTTP Response (200 OK)|                                                               |
    |<-------------------------|                                                               |
```

## Production-Grade Code: Gateway Introspection Middleware

Below is an Express middleware written in TypeScript implementing secure, optimized RFC 7662 token introspection with connection keep-alive, strict timeout limits, and local memory-backed caching.

```typescript
import { Request, Response, NextFunction } from 'express';
import axios from 'axios';
import Agent from 'agentkeepalive';

// Configure a high-performance keep-alive agent to reuse TCP sockets for introspection calls
const keepAliveAgent = new Agent({
  maxSockets: 100,
  maxFreeSockets: 10,
  timeout: 60000,
  freeSocketTimeout: 30000,
});

const axiosInstance = axios.create({
  httpAgent: keepAliveAgent,
  timeout: 2000, // Strict 2-second timeout to prevent gateway starvation
});

interface IntrospectionResponse {
  active: boolean;
  scope?: string;
  client_id?: string;
  sub?: string;
  exp?: number;
  [key: string]: any;
}

// In-Memory cache for introspection states to avoid hammering the AS
const introspectionCache = new Map<string, { data: IntrospectionResponse; expiresAt: number }>();

const INTROSPECT_URL = process.env.INTROSPECT_URL || 'https://auth.serenya.internal/oauth2/introspect';
const GATEWAY_CLIENT_ID = process.env.GATEWAY_CLIENT_ID || 'gateway-proxy-service';
const GATEWAY_CLIENT_SECRET = process.env.GATEWAY_CLIENT_SECRET || 'super-secret-auth-gateway-credentials';

/**
 * Middleware: Perform cached Token Introspection conforming to RFC 7662
 */
export async function oauth2TokenIntrospection(
  req: Request,
  res: Response,
  next: NextFunction
): Promise<void> {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    res.status(401).json({ error: 'Missing or malformed Authorization header' });
    return;
  }

  const opaqueToken = authHeader.split(' ')[1];

  // 1. Check local cache to bypass external HTTP calls
  const cached = introspectionCache.get(opaqueToken);
  const now = Math.floor(Date.now() / 1000);

  if (cached && cached.expiresAt > now) {
    if (!cached.data.active) {
      res.status(401).json({ error: 'Revoked or inactive token context' });
      return;
    }
    req.user = cached.data;
    next();
    return;
  }

  try {
    // 2. Execute POST request against AS Introspection Endpoint
    const basicAuth = Buffer.from(`${GATEWAY_CLIENT_ID}:${GATEWAY_CLIENT_SECRET}`).toString('base64');
    
    const params = new URLSearchParams();
    params.append('token', opaqueToken);
    params.append('token_type_hint', 'access_token');

    const response = await axiosInstance.post<IntrospectionResponse>(
      INTROSPECT_URL,
      params.toString(),
      {
        headers: {
          'Content-Type': 'application/x-www-form-urlencoded',
          'Authorization': `Basic ${basicAuth}`,
        },
      }
    );

    const introspectionResult = response.data;

    if (!introspectionResult || typeof introspectionResult.active !== 'boolean') {
      throw new Error('Invalid response structure from introspection endpoint.');
    }

    // 3. Cache the introspection output
    // Determine dynamic TTL (use token's exp claim if available, capping at 60s max)
    const ttlSeconds = introspectionResult.exp 
      ? Math.min(60, introspectionResult.exp - now) 
      : 30; // default to 30s TTL if no exp claim is present

    if (ttlSeconds > 0) {
      introspectionCache.set(opaqueToken, {
        data: introspectionResult,
        expiresAt: now + ttlSeconds,
      });
    }

    if (!introspectionResult.active) {
      res.status(401).json({ error: 'Invalid or revoked token' });
      return;
    }

    // Inject identity context downstream
    req.user = introspectionResult;
    next();
  } catch (error: any) {
    console.error(`RFC 7662 Introspection Failure: ${error.message}`);
    // Return 503 instead of 401 when the authentication service goes down to indicate upstream failure
    res.status(503).json({ error: 'Authentication service temporarily unavailable' });
  }
}
```

## Introspection Security Requirements

- **Client Authentication:** The introspection endpoint MUST require client authentication (e.g., Basic Auth, OAuth client credentials, or mTLS) to prevent unauthorized token leakage.
- **Payload Scoping:** The AS should sanitize the returned JSON payload, stripping unnecessary claims or user details based on the identity of the microservice making the introspection query.
- **Cache Invalidation:** Ensure the gateway cache can be actively invalidated via Webhooks or Redis Pub/Sub if a token is explicitly revoked before its local cache TTL expires.
